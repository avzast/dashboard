# Дашборд регистраций на мероприятие

Одна страница [index.html](index.html): открывается двойным кликом, без интернета и без установки программ.

> Файл `registrations.csv` с данными участников в репозиторий не входит (в нём имена людей). Дашборд работает и без него: в страницу встроена обезличенная копия (город, канал, оплата). Свежий CSV можно открыть кнопкой на странице.

## 1. Мой промпт

Исходный текст лежит в [prompt.md](prompt.md):

> Задача: сделай дашборд регистраций на мероприятие по файлу registrations.csv.
> Контекст: я организатор ивента. Мне нужно за минуту понять, сколько людей зарегистрировалось, сколько оплатило и откуда они пришли.
> Формат: одна страница index.html, открывается двойным кликом в браузере, без интернета и без установки программ. Сверху 3 крупные цифры: всего / оплатили / не оплатили. Ниже — таблица по каналам и таблица по городам.
> Готово, когда: всего 30 регистраций, оплатили 20, не оплатили 10.
> Сначала задай мне 3 уточняющих вопроса, потом делай.

## 2. Что нашёл аудит

Полный текст: [audit.md](audit.md). Расчёты в первой версии были верными (30 / 20 / 10), слабости были вокруг данных и устойчивости.

**Существенные риски**
- **Снимок вместо живых данных.** Страница не читает `registrations.csv`, а показывает вшитую копию. После изменения файла цифры тихо устаревают, а даты среза на странице нет.
- **Персональные данные внутри HTML.** Все имена участников лежали в `index.html`, и при пересылке страницы уходил бы полный список с оплатой.
- **Хрупкий разбор CSV.** `split(",")` ломается на запятых в кавычках и привязан к номерам колонок. При строке с недостающими колонками страница оставалась с прочерками и без сообщения об ошибке.
- **Всё, кроме «да», считалось неоплатой.** «Да!», «yes» или «оплачено» молча превращались в «не оплатили».

**Средние проблемы**
- Нет нормализации категорий: «Telegram» и «telegram» стали бы разными каналами, а «Алматы» и «алматы» разными городами.
- Значения подставлялись в `innerHTML` без экранирования, а данные приходят из формы регистрации.
- Проценты на малых выборках (2 из 2, 6 из 6) выглядят слишком убедительно.
- Выводы вроде «Email конвертируется лучше всех» сделаны на 6 регистрациях, а канал смешан с типом билета.
- Итоги и таблицы считаются из одного массива, поэтому согласованность сама по себе ничего не доказывает.

**Слабые места проверки**
- Страница не проверялась глазами: телефон, тёмная тема.
- Нет проверок на других данных: пустой файл, битая строка.

**Мелочи:** мелкий шрифт заголовков, декоративный прогресс-бар, нет переключателя темы, нет пояснения, что считается «оплатил», не используются колонки даты и типа билета.
